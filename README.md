# Пространство

Маркетплейс вроде Ozon/WB, но с низкой комиссией (до 10%), чатами с продавцами, ИИ-ассистентом и сообществом, где участники делятся ростом и получают очки на лимитированные призы.

Сейчас это рабочий прототип: веб-приложение (PWA), которое без переделок оборачивается в iOS-приложение.

## Что есть

| Раздел | Что работает |
|---|---|
| **Главная** | калькулятор «сколько получит продавец» (10% против 15–25%), популярные товары, свежие посты сообщества |
| **Магазин** | каталог и остатки из базы, поиск, категории, карточка товара с раскладкой «мастер получит / комиссия», корзина с учётом остатка, оформление заказа без регистрации (доставка СДЭК или курьер, подарок с открыткой и упаковкой), «Мои заказы» с отменой |
| **Сообщество** | лента постов с темами и лайками, публикация своего поста (+очки за первый пост дня), кейсы с целями и прогрессом, запросы участников |
| **Чаты** | диалоги с продавцами (товар прикрепляется к сообщению), отклик на запросы, закреплённый чат с ИИ |
| **ИИ-ассистент** | YandexGPT или GigaChat: подбирает товары из каталога, считает экономику продаж, рассказывает про призы; ключ API только на сервере |
| **Призы** | лимитированные дропы с остатком и таймером (маскот Пространства и др.), задания на день, серия дней, мои призы с кодами |
| **Аккаунт** | регистрация по email с кодом подтверждения, вход, сброс пароля, профиль, выход, удаление аккаунта; прогресс хранится в базе и синхронизируется между устройствами |

## Запуск у себя

Нужен Node.js 22.13+.

```bash
npm install
cp .env.example .env      # ключи можно заполнить позже
npm start                 # http://localhost:3000
```

Без настроек сайт работает сразу: база создаётся в файле `data/app.db` (SQLite), а коды подтверждения
печатаются в консоль сервера вместо отправки письма. Не хватает только ответов ИИ.
Проверка: http://localhost:3000/api/health покажет, какая база и какой ИИ подключены.

## Структура

```
public/              ← всё, что уходит в браузер / в iOS-приложение
  index.html
  css/app.css
  js/config.js       ← комиссия, адрес API, пороги (без секретов!)
  js/data.js         ← демо-данные ленты и призов; каталог — запасной, если сервер недоступен
  js/bridge.js       ← мост JS ↔ Swift (haptic, share, бейдж, события)
  js/app.js          ← логика приложения
  manifest.webmanifest, sw.js, icons/
server/server.js     ← раздача статики и маршруты /api
server/auth.js       ← регистрация, вход, профиль, прогресс
server/shop.js       ← каталог, заказы, отмена заказа
server/seed.js       ← стартовый каталог (записывается в пустую базу)
server/db.js         ← PostgreSQL / SQLite
server/mail.js       ← отправка кодов на почту
server/ai.js         ← YandexGPT / GigaChat
Dockerfile, docker-compose.yml
```

## Аккаунты и база данных

Как устроено:
- **Регистрация:** email + пароль → на почту приходит 6-значный код (действует 15 минут, 5 попыток) → аккаунт подтверждён.
- **Пароли** хранятся только в виде хэша (scrypt). Сессия — cookie `HttpOnly` на 30 дней, в базе лежит только её хэш.
- **Защита:** не больше 10 попыток входа в минуту с одного IP. API принимает только JSON, поэтому чужой сайт не может отправить запрос от имени пользователя.
- **Что хранится:** профиль (имя, город, телефон, «я продавец») и прогресс (корзина, чаты, очки, призы, посты и лайки).
  Гостевой прогресс переносится в аккаунт при первом входе.
- **Без входа нельзя** забрать приз. Заказ оформить можно и без входа (см. ниже).

**База данных:**
- задан `DATABASE_URL` → **PostgreSQL** (для живого сайта);
- не задан → **SQLite** в файле `data/app.db` (для разработки).

Таблицы создаются автоматически при запуске: `users`, `sessions`, `email_codes`, `user_state`,
`sellers`, `products`, `orders`, `order_items`. В пустую базу записывается стартовый каталог из `server/seed.js`.

## Каталог и заказы

- **Каталог** (`GET /api/catalog`) приходит с сервера вместе с остатками. Если сервер недоступен, показывается демо-каталог из `data.js`.
- **Цены считает сервер.** Браузер присылает только id товаров и количество, поэтому подменить цену нельзя.
- **Остаток списывается при оформлении** одной транзакцией: если двое покупают последний товар, второй получит
  «закончился», а не заказ без товара. Отмена неоплаченного заказа возвращает товар в остаток.
- **Комиссия** записывается в каждую позицию заказа по ставке продавца (`sellers.commission_bp`, 1000 = 10%).
  Так её можно будет снижать для Pro-продавцов.
- **Заказ без регистрации.** Покупатель указывает имя, телефон и почту. Если аккаунта с этой почтой нет, сервер создаёт
  его и присылает код. После ввода кода покупатель входит в аккаунт, заказ появляется в «Моих заказах», а пароль
  можно задать через «Забыли пароль?». Если почта уже зарегистрирована, заказ привяжется после входа.
  Заказ привязывается к аккаунту только после того, как почта подтверждена.
- **Статусы:** `awaiting_payment` → `paid` → `shipped` → `delivered`, или `cancelled`. Сейчас все заказы ждут оплаты:
  оплата (ЮKassa) и расчёт доставки (СДЭК) — следующие шаги.
- **Подарочная упаковка** стоит 300 ₽, меняется в `.env`: `GIFT_WRAP_PRICE`.
- Не больше 5 заказов в минуту с одного IP: заказ без входа отправляет письмо, это защита от спама.

Где смотреть заказы, пока нет админки: таблица `orders` в базе (номер, контакты, адрес, сумма, комиссия) и `order_items` (состав).

**Почта (SMTP).** Для живого сайта настройте отправку писем:
- **Яндекс 360 для бизнеса** (почта на своём домене): `smtp.yandex.ru`, порт 465. В `SMTP_PASS` — пароль приложения
  (Яндекс ID → Безопасность → Пароли приложений).
- **Mail.ru:** `smtp.mail.ru`, порт 465, тоже пароль приложения.
- **Много писем:** Unisender, SendPulse, Notisend — у них есть SMTP с российскими серверами.

`MAIL_FROM` должен совпадать с ящиком, от имени которого вы отправляете.

## ИИ-ассистент (работает в РФ)

Сервер поддерживает **YandexGPT** и **GigaChat**. Оба доступны из России и оплачиваются российской картой.
Ключи лежат только на сервере, браузер их не видит.

### YandexGPT (рекомендуется)

1. Зайдите на [console.yandex.cloud](https://console.yandex.cloud) и создайте платёжный аккаунт (новым пользователям дают грант).
2. Откройте каталог (по умолчанию `default`). Его ID видно на странице каталога, это `YANDEX_FOLDER_ID`.
3. **Сервисные аккаунты** → «Создать» → роль `ai.languageModels.user`.
4. В сервисном аккаунте: «Создать новый ключ» → «API-ключ». Скопируйте секрет в `YANDEX_API_KEY`.
5. Модель: `yandexgpt-lite/latest` дешевле и быстрее, `yandexgpt/latest` умнее.

### GigaChat (Сбер)

1. Зайдите на [developers.sber.ru](https://developers.sber.ru/studio) → GigaChat API → создайте проект.
2. Скопируйте **«Ключ авторизации»** в `GIGACHAT_AUTH_KEY`. Для физлиц есть бесплатный лимит (`GIGACHAT_SCOPE=GIGACHAT_API_PERS`).
3. Серверы GigaChat используют сертификат Минцифры. В Docker он ставится автоматически. При запуске без Docker
   скачайте [корневой сертификат](https://www.gosuslugi.ru/crt) и запустите сервер с `NODE_EXTRA_CA_CERTS=/путь/к/russian_trusted_root_ca.pem`.

## Выложить сайт в интернет (хостинг в РФ)

Проект собирается из `Dockerfile`, поэтому подойдёт любой хостинг с Docker.

**Проще всего: Timeweb Cloud → Apps + управляемая база** (или аналог у Selectel / Yandex Cloud):
1. «Базы данных» → создайте **PostgreSQL**. Скопируйте строку подключения (`postgres://user:pass@host:5432/db`).
2. «Apps» → «Создать приложение» → Docker → подключите GitHub-репозиторий и ветку.
3. В переменных окружения укажите:
   - `DATABASE_URL` — строка подключения к базе (если хостинг требует SSL — ещё `DATABASE_SSL=1`);
   - `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`;
   - `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`;
   - `TRUST_PROXY=1`.
4. Порт `3000`. После сборки вы получите адрес с HTTPS, потом можно привязать свой домен.

⚠ **Не используйте SQLite в Apps:** файл базы стирается при каждом обновлении приложения. Нужен PostgreSQL.

**На своём VPS** (Ubuntu с установленным Docker) — сайт и PostgreSQL одной командой:
```bash
git clone https://github.com/lastic6599-png/prostranstvo.git && cd prostranstvo
cp .env.example .env && nano .env      # обязательно POSTGRES_PASSWORD, плюс SMTP и ключи ИИ
docker compose up -d --build
```
База хранится в Docker-томе `pgdata` и не теряется при обновлении. Для HTTPS и домена поставьте перед сервером
nginx или Caddy. Резервная копия: `docker compose exec db pg_dump -U prostranstvo prostranstvo > backup.sql`.

**152-ФЗ.** Сайт хранит email, имя и телефон, а это персональные данные. Их нужно хранить на серверах в РФ
(российский хостинг это решает). Ещё нужно:
- опубликовать политику обработки персональных данных;
- подать уведомление в Роскомнадзор (pd.rkn.gov.ru).

## Как сделать iOS-приложение

### Вариант 1 — Capacitor (рекомендуется)

Нужен Mac с Xcode.

```bash
npm i @capacitor/core @capacitor/cli @capacitor/ios
npx cap init "Пространство" app.prostranstvo --web-dir public
npx cap add ios
npx cap open ios          # откроется Xcode → Run
```

- В `public/js/config.js` укажите `API_BASE: 'https://ваш-сервер'`, так как файлы внутри приложения лежат локально.
- На сервере: `ALLOWED_ORIGINS=capacitor://localhost`.
- Иконка 1024×1024 лежит в `public/icons/icon-1024.png`.
- Плагины для следующего шага: `@capacitor/push-notifications` (сообщения в чатах, ответы на посты, старт дропа), `@capacitor/haptics`, `@capacitor/share`.

### Вариант 2 — своя оболочка на Swift (WKWebView)

`bridge.js` уже шлёт сообщения в `window.webkit.messageHandlers.native`:

```swift
let config = WKWebViewConfiguration()
config.userContentController.add(self, name: "native")
config.allowsInlineMediaPlayback = true
config.mediaTypesRequiringUserActionForPlayback = []

func userContentController(_ c: WKUserContentController, didReceive m: WKScriptMessage) {
    guard let body = m.body as? [String: Any], let type = body["type"] as? String else { return }
    switch type {
    case "haptic": UIImpactFeedbackGenerator(style: .light).impactOccurred()
    case "badge":  // UNUserNotificationCenter.current().setBadgeCount(...)
        break
    default: break
    }
}
// Из Swift можно открыть экран: webView.evaluateJavaScript("App.switchTab('chats')")
```

### Что важно для App Store

- **Физические товары оплачиваются любой платёжкой** (ЮKassa, CloudPayments, Apple Pay), а не через In-App Purchase. Комиссия Apple на них не распространяется.
- **Посты, чаты и запросы — это пользовательский контент.** Apple требует кнопки «пожаловаться» и «заблокировать», модерацию и принятие правил (Guideline 1.2).
- **Нужен вход** (Sign in with Apple, если есть вход через соцсети) и **удаление аккаунта из приложения** (5.1.1).
- **Розыгрыши призов:** сейчас призы обмениваются на очки, это не лотерея. Если добавите случайный выигрыш, нужны официальные правила и пометка, что Apple не спонсор (5.3).
- **Голый сайт в обёртке отклоняют** (4.2). Нативные пуши, haptics и share помогают пройти ревью.

## Что дальше (до продакшена)

1. **Посты и чаты в базе.** Пользователи, товары и заказы уже там. Чатам нужен WebSocket, ленте — модерация и жалобы.
2. **Очки и дропы считать на сервере.** Сейчас прогресс сохраняется в базе, но рассчитывается в браузере, поэтому
   его можно подделать. Начисление очков, списание и резерв приза (общий лимит на всех) должен делать сервер одной операцией.
3. **Кабинет продавца:** загрузка товаров, выплаты, статистика.
4. **Оплата и доставка:** ЮKassa (чеки 54-ФЗ, агентская схема для продавцов), расчёт и выбор ПВЗ СДЭК, письма о статусе заказа, админка заказов.
5. **Сообщество:** комментарии к постам, фото в постах, подписка на авторов, кнопка «пожаловаться».
